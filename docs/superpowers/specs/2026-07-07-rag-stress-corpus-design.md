# RAG 压力测试知识库设计：电力现货与虚拟电厂

## 目标

创建一套仅包含 Markdown 文件的高难度知识库，用于测试 DocuMind 在复杂检索场景下的 RAG 能力。语料库模拟企业内部知识库，主题限定为电力现货市场、虚拟电厂、储能聚合、调度、结算与碳核算。

这套语料需要同时压测四类能力：

- 高难问答检索：密集术语、长段规则、多条件判断。
- 冲突与版本识别：试行版、修订版、区域补充、废止条款并存。
- 引用精确性：答案需要定位到条款、公式、表格、案例或例外条件。
- 多跳推理：需要跨政策、手册、结算示例、FAQ、事故复盘、附件交叉验证。

## 与当前项目的契合点

当前 RAG 服务只支持 Markdown ingestion。它会先按 Markdown 标题切分，再用约 1000 字符 chunk 和 100 字符 overlap 做递归切分。因此测试语料应做成多份 `.md` 文件，并使用稳定标题、深层小节、表格、公式和近义术语，让 chunk 选择更有区分度。

语料目录：

`docs/rag-stress-corpus/energy-vpp-market/`

本次只新增测试文档，不修改应用代码。文档可通过现有 Knowledge Base 页面上传，也可供后续脚本批量 ingestion 或评测使用。

## 难度设计

文档应包含以下设计：

- 密集领域词：节点电价、偏差电量、SOC 下限、基线负荷、响应容量、结算周期、平衡调整、绿证归属、边际排放因子。
- 近义但不可互换的概念：申报容量、认证容量、可用容量、响应容量、结算容量。
- 版本冲突：2025 废止版和 2026 修订版都看起来像正式规则，只有生效日期和废止说明能区分。
- 区域覆盖：华东和南网附件只在命名场景下覆盖总规则，其他场景仍适用总规则。
- 跨文档链路：正确答案常需要至少两份文档，例如调度资格 + 结算公式 + 碳处理。
- 表格与公式：使用 Markdown 表格和符号公式测试 chunking 与引用恢复。
- 长例外条件：使用多层例外列表，让只命中最近语义 chunk 的检索容易漏条件。
- FAQ 陷阱：FAQ 的简化答案可辅助理解，但正式结算或合规问题不能只引用 FAQ。
- 事故复盘：通过时间线、遥测质量、SOC、区域规则和结算公式共同判断责任。

## 内容约束

语料是合成测试文档，不能声称是真实监管文件。每份文档都需要包含类似声明：

> 本文档为 RAG 评测用合成测试材料，不构成法律、市场、工程或合规建议。

文档应足够自洽，便于人工核对答案；同时要足够复杂，让简单关键词检索容易产生看似合理但错误的结果。

不同文档应有不同写作风格：

- 正式规则使用条款编号和规范性语言。
- 调度手册使用流程、阈值和操作清单。
- 结算材料使用公式、示例和对账说明。
- FAQ 使用简短运营问答，并保留必要 caveat。
- 事故复盘使用时间线、证据、根因和整改项。
- 变更映射使用表格连接旧条款、新条款和替代范围。

## 测试指南要求

索引和测试指南应包含一组紧凑评测题及期望命中文档。它不应包含完整答案，避免 RAG 仅凭指南就答出所有问题。题型包括：

- 单条款查找。
- 多跳结算计算。
- 版本冲突识别。
- 区域覆盖判断。
- FAQ 陷阱规避。
- 事故复盘重建。
- 碳核算与绿证重复计算判断。

每个建议问题应列出期望来源文档，以及这些文档为什么必要。

## 验收标准

实现完成时应满足：

- 目标目录包含 12 份 Markdown 文件。
- 每份文件都有明确标题、合成声明、文档元数据和多层标题结构。
- 2025 与 2026 市场规则包含有意设计且可解释的冲突。
- 至少 6 份文档包含表格。
- 至少 3 份文档包含公式或计算示例。
- 至少 5 个建议评测问题需要引用多份文档。
- 不修改应用代码。
- 所有语料可被现有 Markdown-only ingestion 管道处理。

## 不做范围

- 不构建自动上传器。
- 不修改 chunking、embedding、reranking 或 RAG 服务逻辑。
- 不加入真实监管原文。
- 不创建 PDF、Word 或其他非 Markdown 资料。
