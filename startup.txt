项目启动命令
============

项目根目录：
D:\project\chatLLM

说明：
- 依赖和 .env 配置如果已经准备好，优先用根目录的一条命令启动。
- 这个项目当前使用 npm。如果你自己是用 pnpm 安装依赖的，可以把 npm run dev 换成 pnpm run dev。


推荐启动方式
------------

cd D:\project\chatLLM
npm run dev

或者：

cd D:\project\chatLLM
pnpm run dev


这个命令会自动：
- 检查 server/.env 和 rag-service/.env 是否缺关键配置
- 检查后端 / 前端 / RAG 端口是否已经被其他进程占用
- 启动 PostgreSQL / MinIO / Milvus / Attu / Elasticsearch / Neo4j
- 后端启动时自动执行 server/migrations 里尚未应用的数据库迁移
- 启动后端 NestJS/Fastify
- 启动 RAG 服务
- 启动前端 React

如果 npm run dev 提示 Port check failed，说明端口已经被别的项目或旧进程占用。
先关闭占用 3000 / 5173 / 8000 的进程，再重新执行 npm run dev。
也可以先单独检查：

cd D:\project\chatLLM
npm run check:ports

如果 GitHub OAuth 登录跳回 localhost 后显示 Authentication failed，并且 details 里有 fetch failed / Connect Timeout Error：
- 说明浏览器可以访问 GitHub，但后端 Node.js 进程没有走本机代理。
- 在 server\.env 里加入与你系统代理一致的地址，例如：

HTTP_PROXY=http://127.0.0.1:7897
HTTPS_PROXY=http://127.0.0.1:7897

- 保存后重新执行 npm run dev。


单独启动命令（调试用）
----------------------

启动数据库 / MinIO / Milvus / Elasticsearch / Neo4j：

cd D:\project\chatLLM
npm run dev:infra


启动后端 NestJS/Fastify：

cd D:\project\chatLLM\server
npm run dev


启动 RAG 服务：

cd D:\project\chatLLM
npm run dev:rag

说明：dev:rag 会优先使用项目根目录 .venv，并校验关键 RAG 依赖是否与 requirements.txt 锁定版本一致；不匹配的虚拟环境或系统 Python 不会被启动。


启动前端 React：

cd D:\project\chatLLM\client
npm run dev


访问地址
--------

前端：
http://localhost:5173

后端健康检查：
看 server/.env 里的 PORT。
如果 PORT=3000，就是：
http://localhost:3000/health
http://localhost:3000/health/live
http://localhost:3000/health/ready

后端指标：
需要带上 server/.env 里的 METRICS_TOKEN：

cd D:\project\chatLLM
$env:METRICS_TOKEN=(Select-String -Path .\server\.env -Pattern '^METRICS_TOKEN=').Line.Split('=',2)[1]; Invoke-RestMethod -Headers @{ Authorization = "Bearer $env:METRICS_TOKEN" } http://localhost:3000/metrics

RAG 健康检查：
http://localhost:8000/health
http://localhost:8000/health/ready

简单压测 / 冒烟检查：

cd D:\project\chatLLM
npm run load:smoke

容量配置检查：

cd D:\project\chatLLM
npm run check:capacity

运行中健康巡检（项目启动后再执行）：

cd D:\project\chatLLM
npm run check:ops

企业级容量检查（会提示高并发/大数据场景下偏弱的配置）：

cd D:\project\chatLLM
$env:CAPACITY_PROFILE="enterprise"; npm run check:capacity

RAG 端到端冒烟检查（不消耗外部 embedding API 额度）：

cd D:\project\chatLLM
npm run rag:smoke

这个命令会临时启动一个使用本地 deterministic embedding 的 RAG 服务，自动写入临时 MinIO / PostgreSQL 数据，验证 ingest -> Milvus -> retrieve，然后清理临时数据。

如需指定目标和并发：

cd D:\project\chatLLM
$env:LOAD_TARGET_URL="http://localhost:3000"; $env:LOAD_REQUESTS="100"; $env:LOAD_CONCURRENCY="10"; npm run load:smoke

如需按场景压测健康检查 / 混合接口：

cd D:\project\chatLLM
$env:LOAD_SCENARIO="mixed"; $env:LOAD_REQUESTS="300"; $env:LOAD_CONCURRENCY="30"; $env:LOAD_MAX_FAILURE_RATE="0.01"; $env:LOAD_P95_MS="500"; npm run load:scenario

MinIO 控制台：
http://localhost:9001

Attu / Milvus 管理界面：
http://localhost:3001

Elasticsearch：
http://localhost:9200

Neo4j Browser：
http://localhost:7474


停止项目
--------

前端 / 后端 / RAG：
在对应终端按 Ctrl + C

Docker 基础设施：

cd D:\project\chatLLM
docker compose down
