# 整改路线图

按批次推进，避免同时改运行时、缓存和半个前端。每批结束应达到对应「完成定义」。缺陷详情在 [02](./02-P1-必须修复.md)、[03](./03-P2-P3-缺陷清单.md)；测试在 [07](./07-测试缺口.md)。

## 总原则

1. **先做会污染数据或产生外部副作用的 P1**，再做体验。
2. **服务端兜底**，前端不能当唯一修复（尤其 cancel Run、Continue 跳过 RAG）。
3. **先写回归再改行为**（P1 的 server/rag 测例优先）。
4. **不把「明确不做」做成需求**（DAG、定时任务、重启重放、本地 Shell）。
5. 修完后回写 `docs/agent-platform.md` 里已经不真实的承诺。

## 批次 A — 生命周期与副作用（最高优先）

目标：Agent 再生/删除不再幽灵执行；截断 tool call 不再打外部接口。

| 顺序 | ID | 主要文件 |
|------|-----|----------|
| A1 | P1-LENGTH-TOOLS | `server/src/modules/agents/agent-run.service.ts` |
| A2 | P1-TRUNCATE-RUN | `messages.ts` truncate、delete message/conversation、`agentRuns.ts` complete |
| A3 | P2-EMPTY-BODY | `server/src/lib/llmProviders.ts`（与 A1 同属协议 fail-closed，可同一 PR） |

完成定义：

- T-P1-LENGTH-TOOLS、T-P1-TRUNCATE 通过
- 手工：运行中再生，无第二段幽灵回答、无额外 HTTP 工具请求

## 批次 B — 知识删除可见性

目标：标删除后不能再被检索/缓存引用。

| 顺序 | ID |
|------|-----|
| B1 | P1-DELETE-CACHE |
| B2 | P2-KB-TOAST（同一产品语义：已受理 vs 已删净） |

完成定义：

- T-P1-DELETE-CACHE 通过
- 手工：删文件后立即提问，答案不含该文件

## 批次 C — Continue 语义

目标：续写不再当新问题；Agent 不续写；列表不删错消息。

| 顺序 | ID |
|------|-----|
| C1 | P1-CONTINUE-RAG（服务端 skip RAG） |
| C2 | P2-CONTINUE-PERSIST、P2-AGENT-CONTINUE（服务端拒绝非法 continue） |
| C3 | P1-CONTINUE-MERGE（前端停止错误合并） |

完成定义：

- T-P1-CONTINUE-RAG、T-P1-CONTINUE-MERGE 通过
- 普通聊天 Continue 不再「证据不足」
- Agent 会话无 Continue

## 批次 D — 聊天恢复与首次发送

目标：断线能恢复时间线；空会话发送可靠。

| 顺序 | ID |
|------|-----|
| D1 | P1-SSE-RECOVER |
| D2 | P2-RUN-HISTORY-POLL（同一恢复模型） |
| D3 | P1-FIRST-SEND |
| D4 | P2-FETCH-SILENT、P2-NUMERIC-ID（顺手） |

完成定义：

- T-P1-SSE-RECOVER、T-P1-FIRST-SEND 通过
- 手工：SSE 中断不刷新仍能看到最终回答或审批；连点发送一个会话

## 建议 PR 切分

不要一个 PR 含 A+B+C+D。推荐：

1. PR：A1+A3（协议 fail-closed）
2. PR：A2（truncate 取消 Run）
3. PR：B
4. PR：C
5. PR：D
6. PR：E
7. PR：F/G 按文件集拆

每个 PR 包含对应测试，描述里写缺陷 ID。

## 里程碑

### M0 现状

配置型只读 Agent 可在 happy path 演示。不要演示再生、Continue、断网、写工具。

### M1 预发布只读 Agent

完成 A+B+C+D 的代码与 P1 测试 + 手工清单（07 第 5 节）。  
此时：只读 Agent 可作产品路径；自定义写工具仍建议审批且非默认。

### M2 预发布写工具

M1 + E + `P1-LENGTH-TOOLS` 已在 M1 + staging 白名单 + 密钥流程说明（08）。  
开放 `writes` 审批的 HTTP/MCP。

### M3 抛光

F+G、e2e 增量、文档与 README 同步。
