# 安全、配置与残余风险

本次审查 **未发现** 跨租户鉴权绕过、用户可控 SSRF 直通、上传配额明显竞态绕过。下面区分：已有边界（保持）、配置类缺陷、运维残余风险。不要把「内网 RAG token 模型」当成必须改成用户 JWT 的 P1。

## 1. 已有安全边界（保持）

### 认证与会话

- JWT access + refresh；refresh 存 SHA-256（迁移 `0025`，不可靠旧二进制回滚读明文 token）
- HttpOnly cookie；`NODE_ENV=production` 时 Secure
- GitHub OAuth；本地账号

### 上传与配额

- `MAX_DOCUMENT_BYTES` / `MAX_USER_STORAGE_BYTES` / `MAX_USER_ACTIVE_UPLOAD_BYTES`
- 用户行 `FOR UPDATE` 串行核算
- `reserved_bytes` → 校验成功后转 `storage_bytes`；外部对象确认不存在才释放预留

### Agent 工具

- `AGENT_TOOL_ENCRYPTION_KEY` 派生 AES-256-GCM
- 白名单 + DNS pin + 禁私网 + 禁重定向
- 默认空白名单拒绝自定义远端
- JSON Schema 子集校验模型参数
- 工具结果不可信 + 长度上限 + 系统指令反注入
- 无上下文空间则 **先失败再副作用**
- `never` 审批拒绝 write/high
- 项目作用域：工具不能跨项目绑到 Agent（运行时 fail-closed；配置竞态见 `P2-SCOPE-RACE`）

### RAG

- 服务共享 `X-ChatLLM-RAG-Token`，应只内网可达
- 向量误召回靠 PG 水合丢弃
- 生产只暴露反代 443；RAG 8000、PG、Redis、MinIO、ES、Neo4j、Milvus、PgBouncer 留私网

### 生成

- 有 body 的流要求 `[DONE]`
- RAG 失败停止生成

## 2. 本次要改的安全相关缺陷

| ID | 性质 | 说明 |
|----|------|------|
| P1-LENGTH-TOOLS | 错误副作用 | 残缺 tool call 可能打到外部 HTTP/MCP |
| P1-TRUNCATE-RUN | 错误副作用 + 数据污染 | 旧 Run 继续跑并插回消息 |
| P1-DELETE-CACHE | 数据可见性 | 已删文档在缓存窗口仍被引用（授权用户自己的数据，但是错误披露已删内容） |
| P2-SCOPE-RACE | 配置完整性 | 损坏的 published 绑定导致拒绝服务式失败，不是跨用户 |
| P2-GETBOOLEAN | 配置 fail-open | 非 `false` 字符串变 true |
| P2-EMPTY-BODY | fail-open 生成 | 空回复当成功 |
| P3-MISSING-SPACE | 错误处理 | 注意改 404 时不要泄漏他人空间是否存在 |

`P2-SCOPE-RACE` 运行时已 fail-closed，优先保证目录数据不变脏。

## 3. 配置整改

### `getBoolean`（P2-GETBOOLEAN）

对齐 RAG 的严格布尔。至少覆盖：

- `S3_FORCE_PATH_STYLE`
- 其它走同一 helper 的开关

`scripts/check-env.mjs` / `check:config` 应对非法值失败。

### Agent 环境

使用自定义工具前必须有：

- `AGENT_TOOL_ENCRYPTION_KEY`（独立于 JWT、DB 密码）
- `AGENT_HTTP_ALLOWED_HOSTS` / `AGENT_MCP_ALLOWED_HOSTS`

**密钥轮换：** 当前没有密文重加密流程。直接替换密钥会使已有 tool secrets 无法解密。整改文档/运维手册应写：轮换 = 读出解密 → 新密钥加密写回，或冻结自定义工具。不要当静默功能。

### 生产反代（README 已有，保持检查）

- `TRUST_PROXY_HOPS` 只填真实跳数，开发为 0
- SSE 关缓冲、长读超时
- 上传限制与 `MAX_DOCUMENT_BYTES` 一致
- CSP 由反代配，不要在明文 HTTP 上乱开 HSTS

## 4. 残余风险（知情接受或后续立项）

这些 **本次不作为 P1**，但预发布清单里应有人签字：

1. **RAG 内网 token 模型**  
   持有 `RAG_SERVICE_TOKEN` 即可冒充任意 `user_id`。依赖网络隔离。生产误把 8000 暴露公网即全盘失陷。

2. **Graph / Rewrite / Rerank / Judge 默认关闭**  
   检索质量与「企业宣传」可能不符。用 readiness 与评测 baseline 说话，不要改 fail-open 去「看起来开启」。

3. **维护任务 vs 仍存活的 worker**  
   `failStaleAgentRuns` 在超时后标失败；若 worker 仍在跑，可能和终态竞态。文档已说不重放副作用。应用测试钉住「已终态则 execute 停止」（与 `P3-WAITING-UPDATE` 同类）。

4. **SSE 不断开即不算取消**  
   用户关页后 Agent 仍可能跑到预算耗尽。这是产品选择。可选后续：短 TTL 的「无订阅则暂停」，但会改变文档语义，需单独设计，不要夹在 P1 修复里。

5. **Prompt 注入**  
   已有「工具输出不可信」指令和 grounding。不能证明模型一定遵守。写工具必须审批。只读工具仍可能把恶意文档内容读进上下文。

6. **依赖审计**  
   CI 有 `npm audit` 与 `pip-audit`。本次未解读具体 CVE。发版前看当前流水线是否红。

7. **PgBouncer**  
   可选。应用已避免会话级特性。不要在整改 P1 时顺手改连接模式。

## 5. 威胁对照（简表）

| 威胁 | 现状 | 整改动作 |
|------|------|----------|
| 跨用户读知识 | PG 水合 + 文件 user_id | 保持；修 Milvus 过滤粘滞只为召回质量 |
| SSRF 打内网 | 白名单 + DNS pin | 保持；P1 禁止残缺 tool call |
| 密钥进前端 | secrets 不返回 | 保持；编辑器不要为了 debug 打印配置里的 secret |
| 配额打爆存储 | FOR UPDATE | 保持 |
| 已删知识仍回答 | 缓存窗口 | **P1-DELETE-CACHE** |
| 模型截断乱调用 API | length 仍执行 | **P1-LENGTH-TOOLS** |
| 用户以为停了其实在跑 | 再生不 cancel；SSE UI 停住 | **P1-TRUNCATE-RUN**、**P1-SSE-RECOVER** |
