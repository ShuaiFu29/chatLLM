# P2 / P3 缺陷清单

P2 应在 P1 之后尽快处理。P3 可并入邻近 PR，不要单独拖成大重构。

状态列默认均为 **open**。修复时在本文件改状态并在 PR 里引用缺陷 ID。

## P2

### P2-AGENT-CONTINUE Agent 模式仍允许 Continue

- **模块：** Agent / Chat
- **位置：** `client/src/pages/Chat.tsx`（`canContinue`）、`client/src/stores/useChatStore.ts`（约 611–625 行）、`server/src/modules/chat/chat-stream.service.ts`（约 141–144 行）
- **依赖：** `P1-CONTINUE-RAG`

**问题：** `canContinue` 不区分 `conversation.agent_id`。Continue 把「Please continue...」当作 Agent 的 `question`，服务端复用上一条用户消息 id 再开新 Run。同一 user turn 下可能挂多个 Run / 助手气泡。Agent 的语义是整轮工具循环后一次性落最终答案，普通聊天的续写不适用。

**建议：** 前端 Agent 会话隐藏 Continue；服务端若会话绑定 Agent 且 `continue=true` 返回 400。

**验收：** Agent 会话无 Continue；直接打 API 被拒绝；普通聊天 Continue 仍可用（但跳过 RAG）。

### P2-SCOPE-RACE 仅改 Agent 项目空间时工具绑定可越界

- **模块：** Agent
- **位置：** `server/src/repositories/agents.ts`（约 292–307 行）、`server/src/repositories/agentTools.ts`（约 193–211 行）

**问题：** Service 层先 `validateToolBindings`，但 metadata-only 的 `updateAgentForUser` 在事务内不重检 tool bindings。并发：事务 A 把 Agent 从项目 A 改到 B；事务 B 把已绑定全局工具改为项目 A。交错提交后出现「Agent∈B，tool∈A」的已发布配置。运行时 `resolveAgentRuntimeToolsFromRows` 会 fail-closed，但目录里是损坏的 published Agent，每次聊天都失败。

**建议：** metadata 更新若改 `project_space_id`，事务内锁 Agent 与已绑定工具并重检 scope；或禁止「只改空间不发新版本」。工具更新与 Agent 更新使用一致锁顺序。

**验收：** 并发测试或事务测试无法留下跨项目绑定的 published Agent。

### P2-APPROVAL-EXPIRED 审批过期被记成普通失败

- **模块：** Agent
- **位置：** `server/src/modules/agents/agent-run.service.ts`（`waitForApproval` 约 213–248 行，`classifyAgentFailure` 约 1136–1147 行）

**问题：** 等到 `expires_at` 抛 `Agent approval expired`，无对应分类，最终 `error_code: agent_run_failed`，文案像执行失败。与文档「取消或超时」语义不一致。

**建议：** 独立 `error_code`（如 `agent_approval_expired`），UI 显示「审批已过期」而非「生成失败」。

**验收：** 过期 Run 的 error_code / 时间线文案可区分于工具异常。

### P2-EDITOR-ERRORS Agent/Tool 编辑器吞掉业务错误

- **模块：** Frontend
- **位置：** `client/src/features/agents/AgentEditor.tsx`（约 189–190 行）、`ToolEditor.tsx`（约 141–142 行）

**问题：** 展示 Axios `error.message`（`Request failed with status code 400`），不是 `{ error: "..." }`。配额、仍被绑定、schema 非法时用户看不到原因。

**建议：** 统一从 API 错误体解析 `error` / `message`（项目里若已有 helper 则复用）。

**验收：** 触发 409「工具仍被绑定」时 toast 含服务端文案。

### P2-RUN-HISTORY-POLL 运行记录页对活跃 Run 不轮询

- **模块：** Agent UI
- **位置：** `client/src/features/agents/AgentRunHistory.tsx`（约 64–92 行）

**问题：** 只在挂载与手动刷新时拉取。聊天里审批/取消后，历史页状态过期，容易重复取消或对已决审批再操作。

**建议：** 存在 `queued|running|waiting_approval` 时 1.5–2s 轮询详情；终态停止。与聊天页共用 refresh 间隔即可。

**验收：** 聊天中批准后，不手动刷新即可看到历史页变为 running/succeeded。

### P2-MILVUS-PROBE Milvus 项目字段探测失败会被永久记为 false

- **模块：** RAG
- **位置：** `rag-service/vector_store.py`（约 29–43、185–187 行）

**问题：** 首次 `describe_collection` 瞬时失败会把 `_project_space_field_available = False` 进程内缓存。之后带 `project_space_id` 的向量检索不再过滤项目，候选被错误项目占满 limit，再靠 PG 水合丢弃。不泄漏跨租户，但同用户跨项目召回变差。

**建议：** 失败不要缓存 false；或缓存带 TTL / 下次成功覆盖；启动后定期重探。

**验收：** mock 第一次 describe 失败、第二次成功后，检索请求带上 project 过滤字段。

### P2-EMPTY-BODY 兼容模型流无 body 时静默结束

- **模块：** Chat / LLM
- **位置：** `server/src/lib/llmProviders.ts`（约 280–282、335–338 行）

**问题：** 上游 200 且无 `response.body` 时直接 `return`，不走 `assertCompatibleModelStreamComplete`。有 body 的截断流是 fail-closed，无 body 路径不一致。表现为假成功空回复。

**建议：** `!response.body` 视为协议错误并抛出。

**验收：** 单测无 body → 抛错；聊天/Agent 不落「成功空回答」。

### P2-CONTINUE-PERSIST 无历史用户消息时续写会把合成 prompt 落库

- **模块：** Chat
- **位置：** `server/src/modules/chat/chat-stream.service.ts`（约 141–144 行）

**问题：** `continue=true` 且 `findLatestUserMessageForConversation` 为空时，回落 `insertMessage(..., content)`，把续写指令写入 `messages`。截断后的空会话或异常客户端可触发。与客户端「续写不落库」冲突。

**建议：** 没有可续写的 user/assistant 上下文时返回 400，禁止 insert 合成 prompt。

**验收：** 空会话 `continue: true` → 4xx，messages 表无该英文句子。

### P2-GETBOOLEAN `getBoolean` 把任意非 `"false"` 字符串当 true

- **模块：** Config
- **位置：** `server/src/lib/env.ts`（约 175–177 行）

**问题：** `S3_FORCE_PATH_STYLE=0` / `no` / 拼写错误都会变成 `true`。RAG 侧是严格 `true|false`。易造成错误存储行为却「配置成功」。

**建议：** 只接受 `true`/`false`（大小写可折叠），其余 fail-closed。`check:config` 同步校验。

**验收：** `=0` 启动失败或被拒绝；`=false` 为 false。

### P2-FETCH-SILENT 拉消息失败会把已有会话显示成空欢迎页

- **模块：** Frontend
- **位置：** `client/src/stores/useChatStore.ts`（`fetchConversationMessages` / `selectConversation`，约 628–646 行）

**问题：** 失败只 `console.error`。无缓存时 `loadingMessages` 变 false、列表为空，已有会话看起来像「开始聊天」。

**建议：** toast 错误；保留上次缓存或明确错误态，不要用 empty welcome 冒充空会话。

**验收：** mock messages 500，页面有错误提示且不是 welcome 空态。

### P2-KB-TOAST 知识库删除先 toast 成功

- **模块：** Frontend
- **位置：** `client/src/pages/KnowledgeBase.tsx`（约 93–106 行）

**问题：** 先成功再等接口，失败再 error。用户看到不可信的成功反馈。

**建议：** 等 202/成功后再 toast；或明确「已提交删除，正在清理」。删除是异步 202，文案应区分「已受理」和「索引已清」。

**验收：** 接口失败时从未出现 success toast。

### P2-NUMERIC-ID 乐观消息用纯数字 id，流式中可点分支

- **模块：** Frontend
- **位置：** `client/src/components/ChatMessage.tsx`（约 333 行）、`useChatStore.ts`（`Date.now()` 占位）

**问题：** 分支按钮只排除 `temp-` / `welcome-`。流式中可把无效数字 id 打到分支接口。

**建议：** 乐观 id 统一 `temp-` 前缀；未持久化前禁用分支/删除（或删除仅本地回滚）。

**验收：** 流式过程中分支按钮不可用或点击无请求。

## P3

### P3-EXPIRED-UI 过期审批在时间线画成 rejected

- **位置：** `client/src/features/agents/agentRunEvents.ts`（约 46 行）
- **问题：** `decision: status === 'approved' ? 'approved' : 'rejected'` 把 `expired` 当成拒绝。
- **建议：** 保留 `expired`，i18n 增加过期文案。
- **关联：** `P2-APPROVAL-EXPIRED`

### P3-WAITING-UPDATE 进入 waiting_approval 时忽略 updateAgentRun 失败

- **位置：** `server/src/modules/agents/agent-run.service.ts`（约 1108–1120 行）
- **问题：** 跨实例 cancel 已把 Run 置终态时，`update` 返回 null 仍 `createAgentApproval` + `waitForApproval`，短暂留下挂在已取消 Run 上的 pending approval。500ms monitor 最终会中断。
- **建议：** update 失败则停止创建 approval。

### P3-POOL-RECURSE 连接池对已关闭空闲连接递归 acquire

- **位置：** `rag-service/database_pool.py`（约 58–61 行）
- **问题：** 弹出已关闭连接后递归 `acquire()`，无迭代上限，极端下栈溢出。
- **建议：** 改成循环，跳过 closed 连接。

### P3-MISSING-SPACE 不存在的 project_space_id 被静默当成空 scope

- **位置：** `rag-service/db.py`（约 310–322 行）
- **问题：** 错误/已删 space id 返回伪造 `knowledge_version=1`，检索为空且无 404。
- **建议：** 明确 404 / 空错误码，便于发现调用方 bug。注意：不要把「用户无此空间」做成跨用户信息泄漏。

### P3-TRAILING-SLASH 带尾斜杠的深层路由落到首页

- **位置：** `client/src/App.tsx`（约 43–44 行）
- **问题：** `/agents/` 精确匹配失败。
- **建议：** 规范化 pathname（去尾斜杠，保留 `/`）。

## 其它已观察、未单独立项的问题

整改时若碰到可顺手修，不必专门开 P0/P1：
