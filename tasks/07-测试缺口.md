# 测试缺口与应补回归

现有自动化不少（服务端 50+ `server/test/*.mjs`、RAG `rag-service/tests`、根目录 scripts、client vitest、Playwright 关键流）。**空洞不在「没测试」，而在「聊天生命周期 × Agent / 删除缓存窗口 / Continue」没钉住。**

CI：`.github/workflows/quality.yml` 会跑 lint、`npm test`、build、Playwright。P1 修复必须能进这套门，而不是只靠手工。

## 1. 现有测试地图（避免重复造轮子）

### 服务端（较强）

- 鉴权、JWT、session、rate limit、mutation schema
- 上传配额/分片、清理 jobs、项目空间删除
- RAG client、trigger、trace/eval snapshot、retrieval cache fingerprint
- 平台稳定性（RAG 失败 fail-closed 等）
- **`server/test/agent-runtime.test.mjs`**：计算器、密钥、SSRF 白名单、MCP/HTTP、预取消 intent、completion 占位、`decideAgentToolPolicy`、流完整性辅助函数

### RAG 服务（较强）

- ingestion / conversion generation / 多格式
- retrieval cache fingerprint 与 knowledge_version
- evidence verifier、runtime stability、graph 相关

### 前端（中）

- `useChatStore` 会话隔离、stop
- `useAgentStore` catalog
- navigation、upload、rag report、i18n 静态 key
- e2e happy path

### 明确不足

| 缺口 | 为何危险 |
|------|----------|
| regenerate/truncate × 活跃 Run | P1-TRUNCATE-RUN 可直接回归 |
| `length` + tool_calls 禁止 execute | P1-LENGTH-TOOLS |
| Continue + RAG / + agent_id | P1-CONTINUE-RAG、P2-AGENT-CONTINUE |
| 删除 deleting 后 cache 仍命中 | P1-DELETE-CACHE |
| 完整 `execute()` 多轮 tool→model（mock provider） | 审批/取消/过期 error_code |
| 项目空间 vs 工具并发 | P2-SCOPE-RACE |
| Agent SSE 断线恢复 | P1-SSE-RECOVER，e2e 也没有 |
| MessageList 合并 | P1-CONTINUE-MERGE 无组件测 |
| 首次发送竞态 | P1-FIRST-SEND |
| `failStaleAgentRuns` vs in-process registry | 维护任务与活 worker 边界 |

## 2. P1 必须新增的测试

### T-P1-TRUNCATE（server）

1. 插入 conversation、user message、running `agent_runs` 指向即将被删的 assistant
2. 调 truncate API（或 repository）
3. 断言 Run `cancelled`（或等价终态）
4. 再调用 complete 路径，断言 **不再 insert** 新 assistant
5. 变体：delete conversation、delete assistant message

### T-P1-LENGTH-TOOLS（server，可纯函数/runtime）

1. mock 模型 chunk：完整可 parse 的截断 JSON arguments + `finish_reason=length`
2. spy HTTP/MCP execute，断言 0 次
3. 断言资源上限错误
4. 对照：`finish_reason=tool_calls` 仍 execute（只读 calculator 即可）

### T-P1-DELETE-CACHE（rag-service + 可选 server）

1. 写入精确 cache，documents 含 `file_id=X`
2. 将文件置 `deleting`，**先不调用** cleanup bump（或 bump 与 deleting 的顺序按修复后的契约）
3. retrieve 相同 key：不得返回 file X
4. 保持「bump 后 fingerprint 变化」旧测例仍然通过

### T-P1-CONTINUE-RAG（server）

1. `continue: true` + 会话 `enable_rag=true`
2. mock rag client，断言 0 次 retrieve
3. 变体：绑定 `agent_id` + continue → 400
4. 变体：无 user message + continue → 400，不 insert 合成英文（覆盖 P2-CONTINUE-PERSIST）

### T-P1-FIRST-SEND（client）

1. `sendingMessage` 为 false 时，Chat 发送路径在 create 未完成前第二次 submit 被忽略  
   （可抽 hook/store 测，不一定上 Playwright）
2. create 抛错 → toast（mock）且 input 恢复

### T-P1-SSE-RECOVER（client）

1. 消息上只有 `agentRunId` + `run.started`，无 `agent_run_status`，且 `sendingMessage=false`
2. 断言恢复轮询会 `refreshMessages`（fake timer）
3. 有 `run.completed` 则不轮询

### T-P1-CONTINUE-MERGE（client）

1. 两条相邻真实 UUID 的 assistant **不合并**
2. 删除回调收到的 id 是被点的那条

## 3. P2 建议测试

| ID | 测试要点 |
|----|----------|
| P2-SCOPE-RACE | 并发或交错事务后 bindings 仍合法；非法则事务回滚 |
| P2-APPROVAL-EXPIRED | wait 超时 → 特定 error_code |
| P2-EMPTY-BODY | `streamChatCompletion` 无 body → throw |
| P2-GETBOOLEAN | `0`/`yes` 拒绝；`false`/`true` 正确 |
| P2-MILVUS-PROBE | describe 失败不永久禁用字段 |
| P2-EDITOR-ERRORS | 解析 API error body 的纯函数单测即可 |
| P2-NUMERIC-ID | 乐观消息 `id` 匹配 `/^temp-/` 或分支按钮 disabled |

## 4. e2e 增量（mock-api）

优先加在 `client/e2e`，保持不依赖真 LLM：

1. 首次进入 `/` 发送：只创建一个 conversation（计数 mock POST）
2. Agent 运行中 messages 第二次返回 succeeded，时间线出现最终文本（模拟恢复）
3. 知识删除 500：无 success 文案

不要把 Playwright 写成第二个单元测试套件。

## 5. 手工验收清单（P1 合并前）

在本地 `npm run dev`（完整 infra）上：

1. 发布只读 Agent（agentic_rag），问一句工作区问题，看到工具时间线与引用
2. 运行中点停止，Run 为 cancelled，无后续工具请求
3. 运行中点再生：只有新回答，无幽灵第二段
4. 运行中停代理/断 SSE：不刷新，时间线仍能完成或进入审批
5. 整页刷新：时间线从 DB 恢复
6. 普通聊天 Continue：接着原文，不突然「证据不足」
7. 删除一个已索引文件，立刻再问原问题：不得引用该文件
8. 空工作区连点发送：只有一个会话

写工具 / MCP 手工测放到 P1 之后的 staging。

## 6. 修复时的测试纪律

- 先为 P1 写失败测试再改代码（能做到的模块优先）
- 不跳过 CI hook
- 不把「启动依赖 Docker 的集成测」硬塞进默认 `npm test`，除非仓库已有同类 PG 集成测模式（已有若干 `*-postgres.integration.test.mjs`，truncate×Run 可跟随该模式）
- Agent 完整循环可用 mock provider，不必打真实 DeepSeek
