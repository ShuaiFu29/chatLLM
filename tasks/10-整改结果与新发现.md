## 三、修复过程中新发现的缺陷（已一并修复）

这三个不在 01–08 的清单里，是实施与写测试时暴露出来的。它们都属于既有 P1 的同一根因面，所以直接修掉而没有单独立项排期。

### N1（P1 级，属 P1-TRUNCATE-RUN 面）项目空间清理会重建已删除的助手消息

`cleanupJobs.ts` 的 `cancelProjectSpaceAgentRunsWithClient` 在 `assistant_message_id` 为空时会 `insert into messages`。而这段代码运行时该项目空间的会话正要被级联删除，占位消息为空恰恰说明它已被删掉 —— 于是它会往即将消失的会话里重新插一条消息，与 P1-TRUNCATE-RUN 是同一类「复活已删消息」。已改为只回填仍存在的占位。

### N2（P1 级，属 P1-SSE-RECOVER 面）失败回滚会销毁恢复所需的证据

`useChatStore` 的 `rollbackFailedAssistant` 在流异常结束时移除乐观助手气泡。但 Agent Run 是故意比 SSE 活得更久的，而 `agentRunId` 与事件列表只存在这条气泡上 —— 回滚等于把恢复所需的唯一线索删掉，`hasRecoverableAgentRun` 永远看不到它，轮询不会启动。这个缺陷是 P1-SSE-RECOVER 的回归测试逼出来的：修好判定逻辑后用例仍失败。已改为：该占位仍是可恢复 Run 时不回滚。

### N3（P2 级，属 P2-APPROVAL-EXPIRED 面）审批过期被降级成工具失败

审批过期抛出的错误会被工具循环的 `catch` 吞掉，序列化成 `Tool execution failed` 回喂给模型，Run 继续跑到迭代上限，最终报的是通用失败。即使 `classifyAgentFailure` 认得新错误类型也永远走不到那里。已在该 `catch` 中显式重抛 `AgentApprovalExpiredError`。
