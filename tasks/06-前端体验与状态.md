# 前端体验与状态整改

前端整体中上：`chatRequestState` / 请求代际、会话切换隔离、en/zh 叶子 key 对齐（约 929，互不缺）都比较扎实。问题集中在 **发送生命周期、Agent 恢复、Continue 展示、错误可见性**。

## 1. 聊天发送与会话

### P1-FIRST-SEND

`Chat.tsx` 无会话发送：先 `createConversation`（try 外）再 `sendMessage`。创建期间 `sendingMessage === false`。

还要处理 `createConversation` 内部：

- 乐观 `temp-*` 会话
- 成功后 fire-and-forget `selectConversation(newConv.id)`
- `sendMessage` 用 `get().currentConversationId`

整改清单：

- [ ] 创建+发送同一 lock，连点无效
- [ ] 失败 toast + 恢复 input/draft
- [ ] `sendMessage(content, false, newId)` 显式传 id
- [ ] 活跃 stream 时 fetch 不得覆盖乐观消息
- [ ] 乐观会话 id 与消息 id 都用 `temp-` 前缀（兼修 `P2-NUMERIC-ID`）

### P2-FETCH-SILENT

切会话拉历史失败 → 空白欢迎。应有 error 态：重试按钮、保留 cache、不要 `messages.length === 0` 的 welcome。

### 重命名 / 停写失败无提示

`renameConversation` 失败只 rollback + console（`useChatStore.ts`）。修错误可见性时可统一 toast。

## 2. SSE、停止、恢复

现有优点：

- 停止会 abort 当前会话流，并尝试 `POST /agent-runs/:id/cancel`
- 跨会话隔离有单测

缺口：

| ID | 现象 | 改法要点 |
|----|------|----------|
| P1-SSE-RECOVER | 直播不写 `agent_run_status`，断线不轮询 | SSE 补 status，或用 `agentRunId` + 未完成事件判断 |
| P2-RUN-HISTORY-POLL | 管理页不刷新活跃 Run | 与聊天同一轮询条件 |
| toast「可重试」 | Agent 仍在服务端跑时用户重发 → 重复 user 消息 | 区分 `ChatStreamError`：Agent 未完成应提示「已恢复运行」而非「请重试」 |

`selectConversation` 在 `activeController && cachedMessages` 时直接 return。若 controller 泄漏未释放，切回会话会一直陈旧。修恢复路径时检查 `beginStream` / `stopStream` 是否对称。

## 3. 消息列表与 Continue

`MessageList` 合并相邻 assistant 的本意是去重，但 Continue 会插入 **两条合法助手消息**。

整改：

1. 停止合并持久化后的相邻 assistant（`P1-CONTINUE-MERGE`）
2. Agent 禁用 Continue（`P2-AGENT-CONTINUE`）
3. 普通 Continue 跳过 RAG（`P1-CONTINUE-RAG`）
4. `useDeferredValue` 导致 `messages.length>0` 但 `displayMessages=[]` 的一帧空白：可用 `messages` 做 empty 判断，deferred 只用于渲染内容
5. 加载更早消息时保存 scroll height，恢复锚点，避免跳顶

## 7. e2e 现状 vs 应补

现有 `client/e2e/critical-flows.spec.ts` 大约 7 条，偏 happy path + mock-api：

- 登录
- 发消息看到 SSE 完成
- 选已发布 Agent
- 运行记录取消 waiting Run
- 知识上传
- 引用打开预览

应补（可用 mock，不必真模型）：

- 空会话首次发送不可双发
- Continue 不合并删错（若继续提供 Continue）
- Agent SSE 中断后轮询恢复（mock 第二次 messages 带 running→succeeded）
- 聊天内审批（若 mock 能返回 waiting_approval）
- 删除知识失败不出现成功 toast

单测优先覆盖 store/MessageList，e2e 只钉关键用户路径。详见 [07](./07-测试缺口.md)。
